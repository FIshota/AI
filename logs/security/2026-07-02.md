## 🚨 Critical / High Findings (pip-audit)

### CVE-2026-44405 — paramiko 3.5.1
- **Severity**: HIGH
- **Package**: `paramiko == 3.5.1`
- **Fix Version**: none available yet (upstream patch pending: commit `a448945`)
- **Description**: In Paramiko through 4.0.0, `rsakey.py` permits the SHA-1 algorithm for RSA key signatures. SHA-1 is cryptographically weak and vulnerable to collision attacks.
- **Impact**: Man-in-the-middle attacks on SSH sessions using RSA+SHA-1. AI-chan's `core/server_home.py` uses Paramiko extensively.
- **Mitigation**: Disable SHA-1 key types in SSH config; enforce `PubkeyAcceptedAlgorithms -ssh-rsa` on server side; monitor upstream for patch release.

### CVE-2025-69872 — diskcache 5.6.3
- **Severity**: HIGH
- **Package**: `diskcache == 5.6.3`
- **Fix Version**: none available yet
- **Description**: DiskCache through 5.6.3 uses Python `pickle` for serialization by default. An attacker with write access to the cache directory can achieve arbitrary code execution via malicious pickle payloads.
- **Impact**: RCE if cache directory is writable by untrusted users or processes.
- **Mitigation**: `_secure_cache_dir()` in ai-chan is noted as a mitigation (see `requirements.txt` comment, 2026-04-22). Ensure cache directory permissions are `700` (owner-only). Verify `_secure_cache_dir()` is called on all DiskCache instantiation paths.
