## 🚨 Critical / High Findings

### CVE-2026-44405 — paramiko 3.5.1 (HIGH)
- **GHSA:** GHSA-r374-rxx8-8654
- **Description:** In Paramiko through 4.0.0 before a448945, `rsakey.py` allows the SHA-1 algorithm (deprecated, collision-vulnerable).
- **Fix Version:** No fixed version published yet — monitor upstream. Workaround: configure SSH connections to reject SHA-1 key exchange in server policy.
- **Impact:** SSH key operations may fall back to SHA-1, weakening authentication integrity.

## ⚠ Medium Severity Findings

### CVE-2025-69872 — diskcache 5.6.3 (MEDIUM)
- **GHSA:** GHSA-w8v5-vhqr-4h9v
- **Description:** DiskCache through 5.6.3 uses Python `pickle` serialization by default. An attacker with write access to the cache directory can achieve **arbitrary code execution** when a victim application reads from the cache.
- **Fix Version:** No fixed version published yet — monitor upstream. Workaround: restrict write permissions on the cache directory; consider switching to a JSON-safe serializer.

## Recommendations (Priority Order)

1. **[P1] paramiko CVE-2026-44405** — Disable SHA-1 in SSH negotiation immediately. Pin `paramiko` to a patched release as soon as one is available (watch GHSA-r374-rxx8-8654). The SSH server-management feature in `core/server_home.py` is the primary attack surface.

2. **[P1] diskcache CVE-2025-69872** — Audit cache directory permissions (`0700` recommended). Evaluate replacing pickle with a safe serializer (e.g., `msgpack` or JSON) for cache entries that originate from user-controlled or network-sourced data.

3. **[P2] SQL injection risk (B608)** — `core/conversation_search.py` lines 306 and 368 construct SQL via f-strings. Replace with parameterised queries or use an allowlist for column/table names.

4. **[P2] Shell injection via Paramiko exec_command (B601)** — `core/server_home.py` passes string commands to `exec_command`. Validate and sanitize all command strings; prefer passing commands as lists where the API allows; restrict what commands can be executed from user-triggered flows.

5. **[P3] cryptography major upgrade** — `cryptography 41→49` spans 8 major versions; it likely includes security patches for OpenSSL-related vulnerabilities. Schedule an upgrade with a staging test of all TLS/key operations.
