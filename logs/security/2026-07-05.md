## 🚨 Critical / High Findings

### CVE-2025-69872 — `diskcache` 5.6.3 · **HIGH**

> DiskCache (python-diskcache) through 5.6.3 uses Python pickle for serialization by default. An attacker with write access to the cache directory can achieve **arbitrary code execution** when a victim application reads from the cache.

| Field | Value |
|-------|-------|
| Package | `diskcache 5.6.3` |
| CVE | CVE-2025-69872 |
| Fix Version | No upstream fix published yet — mitigate by restricting cache-dir permissions or switching to a non-pickle backend |
| GHSA | — |

**Mitigation (immediate):** `chmod 700` the cache directory; ensure no untrusted process can write to it. Consider replacing `diskcache` with a cache layer that avoids pickle (e.g., Redis with msgpack, or a SQLite-only store).

## Recommendations (Priority Order)

1. **[P1 — Immediate] Restrict diskcache directory permissions.**
   `CVE-2025-69872` enables RCE via pickle deserialization. Run `chmod 700 <cache_dir>` and audit who can write to it. Plan migration away from pickle-based caching.

2. **[P1 — Immediate] Upgrade `cryptography`.**
   Currently 8 major versions behind (`41.0.7 → 49.0.0`). As a direct transitive dep of `paramiko`, it amplifies `CVE-2026-44405`. Pin `cryptography>=49.0.0` in `requirements.txt` and validate no breaking API changes.

3. **[P2 — This Sprint] Upgrade `paramiko` past commit a448945.**
   Monitor upstream for a tagged release that resolves `CVE-2026-44405` (SHA-1 deprecation). Interim: disable SHA-1 at the `paramiko` client level via `disabled_algorithms`.

4. **[P3 — Next Sprint] Sanitise `cmd` variable in `core/server_home.py:265`.**
   Audit all callers of the SSH exec path. If any caller can accept user-supplied strings, wrap with an allowlist to prevent injection.

5. **[P3 — Next Sprint] Update remaining major-version packages.**
   `launchpadlib`, `wadllib`, `xmltodict`, `yq` — all have breaking-change releases. Schedule a dependency update sprint; test against CI.
