## Recommendations (Priority Order)

1. **[CRITICAL — Immediate] Mitigate diskcache pickle RCE (CVE-2025-69872)**
   No patch is available. Short-term: restrict filesystem permissions on the cache directory so only the application process can write to it. Medium-term: evaluate replacing diskcache with a backend that does not use pickle (e.g. a Redis-backed cache, or configure diskcache with a custom serialiser). Track upstream for a fix.

2. **[HIGH — This Sprint] Audit `core/server_home.py:265` Paramiko exec_command with dynamic `cmd`**
   Verify that `cmd` can never contain attacker-controlled content. If it must accept variable commands, implement a strict allowlist. Add `# nosec B601` with justification only after confirming the call is safe.

3. **[HIGH — This Sprint] Replace / upgrade `ecdsa` or isolate its usage**
   The upstream project will not fix the Minerva timing attack. Audit every use of `ecdsa.SigningKey.sign_digest()` and related APIs. Where possible, migrate to the `cryptography` library (which is already a dependency) for ECDSA operations.

4. **[MEDIUM — This Release] Upgrade `cryptography` from 41.0.7 → 49.x**
   8 major versions behind a security-critical library is a significant risk surface. Run upgrade in a staging environment, check for breaking API changes, and pin the new version in `requirements.txt`.

5. **[MEDIUM — Next Sprint] Validate SQL identifier interpolation in `conversation_search.py`**
   Confirm that `id_c`, `ts_c`, `sp_c`, `txt_c`, `tbl`, `select_score`, `join`, `where_sql`, and `limit` are all validated against a strict allowlist before use. If they are, add `# nosec B608` with an explanatory comment. If any are user-supplied, refactor to parameterised queries or identifier quoting.
